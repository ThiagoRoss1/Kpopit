# Lighthouse baseline — production (kpopit.net), 2026-10-15

Measured **before any Major Patch change** (G1), against the live site.

- Tool: `npx @lhci/cli@0.15.1 collect` (Lighthouse 12.6.1, headless Chrome 155, simulated throttling), run locally on Windows.
- 3 runs per URL; values below are the **median of the 3 runs** per metric.
- Mobile = Lighthouse default (Moto G Power emulation, slow 4G); desktop = `--settings.preset=desktop`.
- Pages: `/`, `/classic`, `/blurry`, `/pixelated`, `/idols`, `/idols/1/kim-chaewon-le-sserafim` (first idol link on `/idols`).
- JS = transfer size of all scripts (`resource-summary`).
- Raw reports (one JSON per run) are kept locally in `mobile/` and `desktop/` next to this file and are not tracked (generated output). Re-summarize with
  `node lighthouse/summarize.mjs lighthouse/baseline/mobile lighthouse/baseline/desktop`.

## Notes

- Mobile performance is the weak spot everywhere (53–69), driven by LCP (5–6.7 s); TBT is low except `/idols` (463 ms).
- `/idols` on desktop has **CLS ≈ 1.0** (the list re-flows while loading) and the lowest performance (64).
- `/pixelated` desktop: performance 74, best practices 96.
- Idol page accessibility: 83 mobile / 90 desktop — lowest a11y score.
- SEO is 100 everywhere (Lighthouse's SEO checks only crawlability/meta basics; it does not measure AEO).
- Every page ships the same single JS bundle (~286 KB transferred).
- Later comparisons run against the local production build (`npm run test:lighthouse`, `vite preview`), so performance numbers are not directly comparable to these; accessibility, best practices and SEO are.
